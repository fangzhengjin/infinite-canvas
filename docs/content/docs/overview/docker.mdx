# Docker Deployment

## Use the published image

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

Open `http://localhost:3000`.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## Mount under a subpath

The same container continues to serve `/` and can expose one additional subpath at startup through `APP_BASE_PATH`, without rebuilding the image:

```bash
APP_BASE_PATH=/tools/canvas docker compose up -d
```

The container then serves both `/` and `/tools/canvas/`. A subpath may contain multiple segments; each segment accepts only letters, numbers, underscores, and hyphens, and a trailing slash is normalized automatically. To prevent one URL from representing both a root application route and the mounted application, the first segment cannot be `image`, `video`, `assets`, `prompts`, `canvas`, or `config`. Invalid values stop container startup with an explicit error.

The host reverse proxy must preserve the original prefix so the container's Nginx can recognize and remove it. For Nginx, keep `proxy_pass` without a trailing slash:

```nginx
location = /tools/canvas {
    proxy_pass http://127.0.0.1:3000;
}

location /tools/canvas/ {
    proxy_pass http://127.0.0.1:3000;
}
```

If the host already strips the subpath before forwarding, leave `APP_BASE_PATH` unset. Root and subpath entry points on the same origin share the existing browser-local data.

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The main application container only runs Next.js. Canvases, My Assets, generation history, and API keys are stored in the browser by default, while prompt repositories are fetched directly by the frontend. No persistent data volume is required for this data.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/basketikun/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
